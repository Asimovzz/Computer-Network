### 实验 A：集线器（Hub）

**拓扑**：四台主机星型接入中心设备 device（集线器/交换机实验共用此拓扑）。

```Plain Text
┌───────────┐
                  │   device  │
                  └┬───┬──┬──┬┘
                   │   │  │  │
        ┌──────────┘   │  │  └──────────┐
        │          ┌───┘  └───┐         │
   ┌────┴───┐ ┌────┴───┐ ┌────┴───┐ ┌───┴────┐
   │ host1  │ │ host2  │ │ host3  │ │ host4  │
   │10.0.0.1│ │10.0.0.2│ │10.0.0.3│ │10.0.0.4│
   └────────┘ └────────┘ └────────┘ └────────┘
```

**程序结构**：集线器收到任一分组后，向**除入端口外的所有端口广播**（不查表、不学习）。

```Plain Text
+-------------+     +---------------+                                       +-------------+
 | device-eth0 |---->| recv thread 0 |--+                                 +->| device-eth0 |
 +-------------+     +---------------+  |                                 |  +-------------+
                                        |   +----------+   +-----------+  |
                                        +-->|pkt buffer|-->| Hub/Switch|--+
                                        |   +----------+   +-----------+  |
 +-------------+     +---------------+  |                                 |  +-------------+
 | device-eth1 |---->| recv thread 1 |--+                                 +->| device-eth1 |
 +-------------+     +---------------+                                       +-------------+
```

**步骤**：

1. 配置容器。

2. 完成 `lab.c` 中的 `Hub()` 函数。

3. 运行测试（见下）。

### 实验 C：路由器与距离向量协议（Router \+ DV）

**拓扑**：四台路由器串成链式，两端各接一台主机。

```Plain Text
┌───────┐                                                                ┌───────┐
   │ host1 │                                                                │ host2 │
   └───┬───┘                                                                └───┬───┘
    1.1│host1-eth0                                                           5.2│host2-eth0
  [10.0.1.0/24]                                                           [10.0.5.0/24]
    1.2│device1-eth0                                                         5.1│device4-eth1
   ┌───┴─────┐[10.0.2.0/24]┌─────────┐[10.0.3.0/24]┌─────────┐[10.0.4.0/24]┌────┴────┐
   │ device1 │─────────────│ device2 │─────────────│ device3 │─────────────│ device4 │
   └────┬────┘2.1       2.2└─────────┘3.1       3.2└─────────┘4.1       4.2└────┬────┘
        ▲ device1-eth1   |     device2-eth1      |     device3-eth1      |      ▲
    初始规则:       device2-eth0            device3-eth0        device4-eth0  初始规则:
<10.0.1.0, 255.255.255.0, device1-eth0>                    <10.0.5.0, 255.255.255.0, device4-eth1>
```

**端口 / 链路对照表**（每条链路一个 `/24` 子网）：

```Plain Text
链路(子网)        端点 A                              端点 B
─────────────    ───────────────────────────        ───────────────────────────
10.0.1.0/24      host1    host1-eth0    .1.1         device1  device1-eth0  .1.2
10.0.2.0/24      device1  device1-eth1  .2.1         device2  device2-eth0  .2.2
10.0.3.0/24      device2  device2-eth1  .3.1         device3  device3-eth0  .3.2
10.0.4.0/24      device3  device3-eth1  .4.1         device4  device4-eth0  .4.2
10.0.5.0/24      device4  device4-eth1  .5.1         host2    host2-eth0    .5.2
```

**程序结构**：收到分组后按 Ethernet Type 分流到控制平面 / 数据平面。实线 = 分组数据流，虚线 `:` = 控制 / 查表信息流。

```Plain Text
+-------------+
                                       +---->|Control Plane|---------+
                                       |     +----+---^----+         |
                                       |          :   :              |
                                 +----------+  +--v---+---+          |
                                 |  DV Pkt  |  |  Route   |          |
                                 |  Buffer  |  |  Table   |          |
                                 +----^-----+  +----+-----+          |
                                      |             :                |  
 +-----------+   +-----------+        |        +----v-----+          |       +-----------+
 |device-eth0|-->|recvThread0|--+     +--------+          |   +------+------>|device-eth0|
 +-----------+   +-----------+  |   +------+   |          |   |      |       +-----------+
                                +-->|pktBuf|-->|  Router  |-->+      |
 +-----------+   +-----------+  |   +------+   |          |   |      |       +-----------+
 |device-eth1|-->|recvThread1|--+              |          |   +------+------>|device-eth1|
 +-----------+   +-----------+                 +----------+                  +-----------+
```

**需完成的子过程**（`lab.c` 中的 `Router()` 与 `control_plane_thread()`）：

1. **初始化**：device1、device4 分别加载初始路由 `10.0.1.0/24`、`10.0.5.0/24`。

2. **分流**：根据 Ethernet Type 识别 DV 协议分组 → 转交控制平面；其他分组 → 数据平面。

3. **数据平面**：查路由表，匹配则转发，不匹配则丢弃。

4. **控制平面**：

    - **处理收到的 DV 消息，更新路由表项**：

        - 路由表中无该目的网络 → 添加表项；

        - 已有匹配表项且其距离 **大于** DV 消息描述的距离（消息中的距离 \+ 1）→ 更新该表项的距离和下一跳；

        - 本实验不添加其他处理逻辑（DV 协议的其他复杂过程参考"五、其他说明 · 5"的 Berkeley 教程）。

    - **定期广播**：将路由表项周期性广播到所有设备端口。

        - 本实验**不考虑**水平分割和毒性逆转（PPT 有简介，后续课程详讲）：

            - 水平分割：一个表项不向自己描述的下一跳广播；

            - 毒性逆转：一个表项向自己描述的下一跳广播正无穷的距离。

        - 本测试不涉及动态拓扑，完成上述链式拓扑连通性即可通过。

**步骤**：

```Bash
make              # 生成 device 可执行文件
make setup_chain  # 启动链式虚拟网络
make test_router  # 测试 router 程序
make clean_chain  # 销毁虚拟网络
```

> 若程序有误，`make test_router` 可能无法自动清空。可执行 `make clean_chain` 后再 `make setup_chain` 重建容器；也可参考脚本中的 `killall` 命令手动清空。
> 
> 

**预期效果**：初始时 device1、device4 各有一条表项；所有 device 每秒广播一次路由表，距离向量沿链式拓扑逐跳传播，**约需几秒才能收敛**。host1 从初始时刻起 `ping` host2 共 10 次（每秒一次）——**前几次因路由尚未收敛会失败，之后成功**，典型完成度为 5–7/10（受机器性能与时序波动影响可上下浮动）。

```Plain Text
root@compnet:/home/wenfeiwu/lab4# make test_router
docker cp device device1:/device          # device2、device3、device4 同样拷贝
docker exec -dit device1 bash -c "./device device1 router"
... device2、device3、device4 同样启动 router ...
docker exec -it host1 bash -c "ping 10.0.5.2 -c 10"
PING 10.0.5.2 (10.0.5.2) 56(84) bytes of data.
64 bytes from 10.0.5.2: icmp_seq=4 ttl=64 time=4xxx ms    # 前几次(seq 1-3)无回应, 从中段开始通
64 bytes from 10.0.5.2: icmp_seq=5 ttl=64 time=4xxx ms
... icmp_seq=6..10 【剩余的icmp记录】...

--- 10.0.5.2 ping statistics ---
10 packets transmitted, 7 received, 30% packet loss
```

> **关于现象说明**：本实验 device 用 libpcap 逐跳收发，端到端 rtt 较高（数秒）。`DV_INTERVAL=1s` 下，DV 沿链式拓扑逐跳传播、约需几秒收敛，`ping`（从 router 启动起）会呈现 **"前几次失败、收敛后成功"** 的过程——这是距离向量逐跳收敛的体现，正确实现典型部分通 **5\~7/10**。
> 
> ⚠ **`DV_INTERVAL=1s`**** 是系统设置值，请勿修改**：把它改小可让收敛变快、ping 接近全通，但这不是正确实现的体现（评测会强制按 1s 计），改动按违规处理。**正确与否取决于是否真正实现了 DV 路由协议**：
> 
> - device 应**周期性广播自己的路由表**（DV 包，`ETH_TYPE_DV=0x88b5`），收到邻居 DV 后更新本地路由表；
> 
> - 路由未收敛时应**丢弃/等待**（表现为前几次 ping 失败），收敛后**按路由表单播转发到下一跳**，而非泛洪。仅靠泛洪让 ping 通（像 Switch 那样，会"立即全通"）不算实现路由；
> 
> - 建议实现**水平分割\(split horizon\)等防环**，否则收敛时易产生环路、`ping` 出现大量 `(DUP!)`（数据包被重复转发）。
> 
> - **评分提示**：Router 共 40 分。**没抓到 DV 协议包（0x88b5）= 未实现 DV 协议，这 40 分为 0**；**出现环路 DUP（大量 ****`(DUP!)`****）从总分扣 10 分**。详见"五、其他说明 · 6 评分方法"。
>

7. **Makefile 的 ****`test_hub`**** 增加一个 ****`sleep 1`**，避免过快 `killall` 导致 ping reply 未被记录：

    ```Makefile
    test_hub:
        docker cp $(TARGET) device:/$(TARGET)
        docker exec -dit device bash -c "./$(TARGET) device hub"
        docker exec -dit host2 bash -c "tcpdump -i host2-eth0 -ne -v > test_hub_host2.log"
        sleep 1
        docker exec -it host1 bash -c "ping 10.0.0.4 -c 3 > test_hub_host1.log"
        sleep 1                        # <- 新增：避免过快 killall 导致 ping reply 未被记录
        docker exec device bash -c "killall $(TARGET)"
        docker exec host2 bash -c "killall tcpdump"
        docker cp host2:/test_hub_host2.log .
        docker cp host1:/test_hub_host1.log .
        @echo "============================================"
        @echo "Display test_hub_host2.log, a correct log should have 6 records"
    ```
